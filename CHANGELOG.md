# История изменений

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

## [Не выпущено]

### Добавлено
- Четыре графовых детектора по официальному датасету кейса — клон SIM (смена IMSI), цепочка переадресации (с кольцевым замыканием),
  SIM-box, карусель; независимая кросс-валидация с официальным датасетом и честно задокументированные ограничения — см.
  [ADR-0019](docs/adr/0019-case-dataset-detectors.md).
- `cmd/cdrflag` — прогон официального датасета кейса (`CDR_*.cdr`) через боевой движок целиком, выгрузка ответа кейса (`submission.txt`).
- Офлайн кросс-валидация графовых признаков через NetworkX при обучении — см. [ADR-0018](docs/adr/0018-networkx-graph-analysis.md).
- «Акт решения» — печатная форма вердикта для надзорного органа, кнопка на карточке решения; кнопка «Скачать PDF» рядом
  формирует настоящий PDF-файл (jsPDF, кириллический Roboto встроен в документ) без диалога печати браузера.
- Разделы «Граф связей» и «Качество модели» панели: визуализация всех четырёх детекторов (двудольный граф, кольцо, радиальные
  спектры, направленные цепочки), кривые ROC/PR/калибровки, матрицы ошибок — вместо текстового описания; реальные скриншоты
  встроены в документацию.
- Раздел «Проблемы»: сводка по общему пулу вызовов, тренд решений по времени, вкладка «Общий пул» (включая `allow` из журнала
  Postgres, не только инциденты), поиск по номеру.
- `/stack-map` — живая карта инфраструктуры и стека.
- Ограничение частоты запросов (`RATE_LIMIT_RPS`), отказ запуска с открытым API по флагу, `/docs` без внешнего CDN.

### Изменено
- Панель полностью переработана в стилистике Material Design 3 (монохромный хром) — вместо информационного дампа текста.
- `cmd/cdrflag` подключён к ML-стадии (CatBoost) флагами `-ml-url`/`-ml-key`; по итогам честного сравнения официальный
  `submission.txt` оставлен на линейной стадии — обоснование в ADR-0019.
- Инфраструктура: лимиты ресурсов и ротация логов в `compose.yaml`, дашборд Grafana.

### Исправлено
- Детектор карусели был слеп к пассивным участникам закрытой группы — закрыт пробел по полному набору.
- Порог проверки (review) превышал собственную цель по доле ложных срабатываний — добавлен запас.
- `graph.AnalyzeChains` мог вернуть разный список цепочек на одном и том же входе (неопределённый порядок обхода map в Go) —
  обход теперь детерминирован, добавлен регрессионный тест.
- Разделы «Качество модели» сами закрывались каждые 3 секунды из-за автообновления панели.
- Причина решения в общем пуле вызовов всегда показывала «—» из-за двойного разбора уже готового JSON.

### Изменено
- Горячий путь: специализированный кодировщик ответа, пулы буферов, проверка уровня логов до сборки записи — обработчик ускорен на 32%
  (1,85 → 1,25 мкс, аллокаций 43 → 31), сквозная пропускная способность 102 → 126 тыс. запросов/с. См. [docs/performance.md](docs/performance.md).
- Ядро подхватывает ML-сервис в течение 5 секунд после его запуска (раньше — до минуты); в JSON-логах версия сборки — поле `build`, без дубля ключа.

### Добавлено
- Нагрузочный тест `cmd/loadtest` (закрытая и открытая модель), отладочный `pprof` (`PPROF_ADDR`, только loopback).
- Панель мониторинга `/ui/` в стиле Zabbix, встроенная в бинарь ядра: показатели, графики, проблемы с разбором факторов, компоненты,
  граф вееров, модель, интерактивная проверка вызова.
- Эндпоинты для панели: `/v1/status`, `/v1/stats`, `/v1/events`, `/v1/model`, `/v1/graph/fans`.
- Телеметрия в памяти (`internal/platform/telemetry`): ряды по секундам и минутам с перцентилями задержки, без блокировок на горячем пути.
- Структурированное логирование (`internal/platform/logx`): форматы json и pretty, `request_id`, компоненты, ограничение частоты горячих событий;
  события состояния (breaker ML, версии моделей, веера); то же в Python-сервисе.

### Изменено
- Структура репозитория: пакеты `internal/` разложены по слоям (`telecom`, `detection`, `decision`, `platform`, `lab`), Python-сервис
  перенесён в `services/ml`, добавлены `docs/`, `Makefile`, линтеры (`staticcheck`, `ruff`) в CI.

## [1.0.0] — 2026-09-29

### Добавлено
- Скоринг вызовов по метаданным: обогащение номеров офлайн-справочником Россвязи, окна по номерам, граф связей («веер»),
  сигналы подмены номера, защитный слой (экстренные службы всегда `allow`).
- Каскад: линейная стадия 1 (Go) и ML-стадия 2 (Python, CatBoost + SHAP) с откатом при сбое.
- Объяснимые решения: факторы с вкладом, жёсткий пол `review` для подмены номера.
- HTTP API, журнал решений в Postgres, метрики Prometheus, `scripts/demo.py`, загрузка внешних выгрузок (`ingest`), оффлайн-прогон файла (`scorefile`).
- Обучение обеих стадий (`scripts/retrain.sh`) на синтетических данных с «трудными» легитимными абонентами.
