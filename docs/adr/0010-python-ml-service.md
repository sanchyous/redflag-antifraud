# ADR-0010: ML — отдельный Python-сервис (CatBoost, scikit-learn)

- **Дата:** 2026-09-28
- **Статус:** Принято

- Решение (по указанию владельца): обучение и онлайн-инференс модели выносятся в микросервис на Python (FastAPI, CatBoost, scikit-learn). Заменяет часть D-01 («всё на Go»): Go остаётся ядром под нагрузку, ML — отдельный сервис.
- Каскад: Go считает все признаки и линейную модель (стадия 1, мкс). Только вызовы «серой зоны» отправляются в ML-сервис (стадия 2: CatBoost + точный TreeSHAP). Недоступность ML → откат на стадию 1 (circuit breaker), вердикт не блокируется из-за сбоя ML.
- Контракт: Go шлёт вектор признаков (имена + значения), ML возвращает score, вклады SHAP, версию модели и пороги.
- Обучение: Go экспортирует датасет признаков (тот же код, что онлайн — нет рассинхрона), Python обучает CatBoost с монотонными ограничениями и линейную модель стадии 1 (sklearn), делит данные по номерам (GroupSplit), подбирает пороги по FPR, пишет отчёт.
- Ограничения: сетевой вызов в серой зоне (бюджет ~5 мс, таймаут, breaker); две среды (Go+Python) в CI и compose.
- Судьба Go-обучения (IRLS в internal/mltrain): заменяется Python-версией; Replay и оценка остаются в Go как экспортёр данных.
