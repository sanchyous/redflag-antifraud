# ADR-0016: Линейная стадия 1 обучается на данных, порядок обучения и выкатки

- **Дата:** 2026-09-29
- **Статус:** Принято

- Решение: стадия 1 (Go, линейная) обучается в `ml-service/training/stage1.py` — логистическая регрессия L-BFGS-B с границами весов (рост признака не снижает риск, кроме длительности), вес легитимных ×3, пороги по FPR. Формат — тот же JSON, что читает `scoring.Load`; контракт закреплён Go-тестом на настоящем файле из Python.
- Обоснование: экспертные веса давали 31% ложных review на независимом наборе, а стадия 1 — запасной решатель при недоступном ML. Обученная: полнота 87,5% при FPR 0,93%, ложных блокировок 0 из 177 тыс.
- Порядок: (1) выгрузка → (2) обучение стадии 1 → (3) повторная выгрузка с `-model stage1.json` (s1 и сильные сигналы считает обученная стадия) → (4) ML с воротами под неё. `scripts/retrain.sh` делает всё за один прогон.
- Выкатка: сначала ML (`rsync` в каталог моделей + `POST /v1/reload`), затем стадия 1 (`config/stage1.json`, `MODEL_FILE`, пересоздать app). Пока версии не согласованы, ворота не совпадают со стадией 1 (короткий период — рост доли трафика в ML или временная потеря полноты).
- Результат каскада: полнота 96,8% при FPR 0,79%, 1 ложная блокировка из 177 610 (корпоративный мультисим), в ML уходит 29% трафика, обычные абоненты 3,8%.
