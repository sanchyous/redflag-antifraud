# Теория: как устроена оценка вызова без прослушки

> Черновые заметки по постановке задачи с самого начала работы над кейсом — в сжатом, тезисном виде.
> Актуальное и подробное изложение того же материала — [architecture.md](architecture.md) (как устроено
> ядро) и [ml.md](ml.md) (как устроено обучение). Документ оставлен как есть — по нему видно, с чего
> начиналось проектирование и что из первоначального плана подтвердилось в реализации.

## 1. Определение региона и оператора без сторонних API
- Источник: открытый реестр Россвязи (ABC-3xx/4xx/8xx, DEF-9xx): `код | от | до | ёмкость | оператор | регион | ИНН`, CSV с разделителем `;`. Формат и кодировку проверять на реальном файле при загрузке (T1.3).
- Номер нормализуется до 10 цифр национальной части; ключ = `код*10^7 + абонентская часть`; диапазоны сортируются, поиск — бинарный (O(log n), ~350k строк, мкс).
- Регион = субъект РФ, где выделен диапазон; **не** место нахождения абонента.
- Оператор по диапазону = оператор выдачи; из-за **MNP** реальный оператор может отличаться. Приоритет: оператор из сигнализации (если есть) → справочник. Расхождение — признак.
- Международные: страна по самому длинному префиксу E.164 (ITU). Для +7 разделять РФ/Казахстан по DEF (76xx/77xx — KZ).
- Справочник версионируется (дата выгрузки), обновляется ежеквартально.

## 2. Spoofing
Заявленный CLI российский (+7 495…), а вход — международный транзит/иностранный оператор источника → сильный сигнал подмены. Слабее, если легитимная роуминг-ситуация: для мобильных DEF с международным входом сигнал мягче, чем для городских ABC.

## 3. Признаки
- По вызову: длительность (лог-шкала), час суток (ночь), тип соединения, страна/оператор источника, отбой на 1-й секунде, spoofing.
- По номеру, окна 1 ч/24 ч: вызовов/час, уникальных собеседников, охват регионов и энтропия, доля коротких (<10 с), доля неотвеченных, out/in ratio.
- По графу: число номеров на абонента; «веер» — группа вызывающих с общим шаблоном и непересекающимися списками получателей (низкий Jaccard между списками при высоком сходстве временных/длительностных шаблонов).

## 4. Скоринг и объяснимость
Логистическая модель: `logit = b + Σ w_i·x_i`. Вклад фактора i = `w_i·(x_i − x̄_i)` относительно базового профиля (эталона нормального абонента) — точное разложение, аналог SHAP для линейной модели. Плюс hard-правила с текстовыми причинами. Оператор получает список факторов со значениями и вкладами — можно отладить и защитить перед регулятором.

Признаки предварительно преобразуются монотонно (лог, клиппинг) — нелинейность без потери объяснимости. GBDT+TreeSHAP — опциональный этап.

## 5. Ложные срабатывания и «скорая»
- Стоимость ошибок асимметрична: блок легитимного (особенно 112/103) — недопустим; пропуск мошенника — потери, но обратимые (review/предупреждение).
- Защитный слой стоит **выше** модели: экстренные и сервисные номера, верифицированные диапазоны (банки/госорганы) → потолок вердикта = review, block невозможен архитектурно.
- Порог block подбирается по целевому FPR (напр. ≤ 0,05%) на валидации; порог review — по FPR ≤ 1–2%.
- Block требует: score ≥ T_block **и** ≥K независимых сильных сигналов **и** не protected.
- Ответ жюри: «что если заблокируем скорую?» → невозможно: тест-доказательство `TestEmergencyNeverBlocked`; и даже при ошибке модели/справочника вердикт для защищённых классов ≤ review.

## 6. Метрики
precision/recall @ FPR, PR-AUC, доля review среди легитимных, доля блоков среди легитимных (должна быть ≈0), калибровка (reliability). AUC — вторично.
