# RedFlag Antifraud — антифрод для звонков по метаданным

Скоринг вызовов **без прослушки**: по одному «конверту» вызова (номера, время, длительность, тип соединения,
страна и оператор источника) система решает `allow`, `review` или `block` и объясняет решение факторами с вкладом.
Кейс №4 хакатона Nexign «Телеком будущего».

## Как закрыты требования ТЗ

| Требование | Как сделано |
|---|---|
| Признаки по вызову: длительность, время суток, тип соединения, страна и оператор источника, отбой на 1-й секунде | `internal/enrich`, `internal/features` |
| Признаки по номеру за окно: вызовов в час, уникальные собеседники, охват регионов, доли коротких и неотвеченных | `internal/window` (окна 1 ч и 24 ч, шарды в памяти, ~200 нс на вызов) |
| Граф связей: номеров на абонента, «веер» — группа номеров с общим шаблоном и непересекающимися списками | `internal/graph` онлайн, горячий путь (Go); офлайн-структура сети и независимая проверка «веера» при обучении — NetworkX, `services/ml/training/graphfeat.py` ([ADR-0018](docs/adr/0018-networkx-graph-analysis.md)) |
| Регион и оператор номера без сторонних API | `internal/numplan` — офлайн-справочник Россвязи (450 тыс. диапазонов, поиск за десятки нс), понимает маски `+7 495 ***-**-12` |
| Объяснимость: факторы с вкладом | точное разложение линейной стадии и **SHAP** у CatBoost; в ответе `reasons[]` со значением, вкладом и фразой |
| Акцент на доле ложных срабатываний | три уровня решения; порог подбирается по целевому FPR; отчёт с ложными срабатываниями по каждому типу абонентов |
| «Что если система заблокирует скорую?» | Невозможно архитектурно: экстренные службы (112, 101, 102, 103, 104) всегда `allow` **до** скоринга и в ML не уходят. Инвариант проверяется тестами на сотнях тысяч случайных комбинаций (`internal/decide`) |
| Автоблокировка — отдельное решение с отдельной ценой ошибки | `block` только при высоком score **и** не менее двух независимых сильных сигналов; проверенные номера (allowlist) и короткие сервисные не блокируются никогда |
| Стек: Python, CatBoost/scikit-learn, NetworkX, FastAPI | ML-сервис `services/ml/` (Python, FastAPI, NetworkX для графового анализа в обучении); ядро под нагрузку на Go |

## Архитектура

```
вызов ─► Go-ядро (decision-api)                                         ┌────────────────────────┐
         экстренные? ─ да ─► allow                                      │ ML-сервис (Python)     │
         обогащение (справочник, spoofing) → окна → граф → признаки     │ CatBoost + TreeSHAP    │
         стадия 1: линейная модель + сильные сигналы (микросекунды)     │ калибровка, пороги     │
         серая зона? ─────────────────────────────────────────────────► │ ~8 мс, необязателен    │
         решение → жёсткий пол подмены → защитные инварианты → ответ ◄─ └────────────────────────┘
         журнал в Postgres (асинхронно)      недоступен ML → откат на стадию 1
```

- **Ядро на Go** держит весь поток: движок ~2,5 мкс на вызов на одном ядре; HTTP-сервис — ~126 тыс. запросов/с на одной машине (p99 2,4 мс, а при 20 тыс. запросов/с p99 = 0,7 мс); состояние — в памяти процесса ([docs/performance.md](docs/performance.md)).
- **Каскад**: только «серая зона» идёт в ML (оценка стадии 1 не ниже ворот либо сильный сигнал). Сбой ML не ломает скоринг: таймаут 50 мс, circuit breaker, откат на стадию 1.
- **Жёсткий пол**: подмена номера (российский номер при иностранном входе) и номер вне распределённых диапазонов — прямое свидетельство, а не вероятность: вердикт не ниже `review` независимо от модели.
- Решения и обоснования — [docs/adr/](docs/adr/README.md).

## API

```bash
curl -s -XPOST localhost:8000/v1/calls/score -d '{
  "call_id": "c-1", "caller": "+7 495 ***-**-12", "callee": "+7 916 ***-**-83",
  "started_at": "2026-10-14T11:42:00+03:00", "duration_sec": 6, "src_country": "DE"
}'
```

Ответ: `decision`, `score`, `reasons[]` (фактор, значение, вклад, фраза), `signals`, регион и оператор сторон,
`stage` (`linear`/`ml`), `rule_floor`, `safe_class`, версии модели и справочника. Спецификация — `GET /openapi.yaml`, Swagger — `/docs`.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/v1/calls/score` | скоринг одного вызова |
| POST | `/v1/calls/score/batch` | до 1000 вызовов по порядку |
| GET | `/v1/calls/recent` | журнал решений (`?decision=block&limit=50`) |
| GET | `/metrics` | Prometheus |
| GET | `/health` | liveness |

Номера в ответах и журнале — только в маскированном виде. Повторная доставка по `call_id` не учитывается дважды.

## Проверка на закрытом наборе жюри

ТЗ прямо указывает: «как оцениваем — на закрытом наборе, с акцентом на долю ложных срабатываний».
`cmd/scorefile` — офлайн-прогон произвольного файла (CSV/JSONL, гибкое сопоставление колонок —
`internal/telecom/ingest`) через тот же боевой движок, что и прод: решение и объяснение на каждый вызов,
а если в файле есть колонка с меткой — сразу сводка полноты и доли ложных срабатываний отдельно для
`review` и для `block`, плюс отдельно экстренные (должно быть 0 заблокированных).

```bash
go run ./cmd/scorefile -numplan /path/to/numplan -in закрытый_набор.csv -out decisions.csv
```

Ничего не нужно разворачивать и обучать заново — только справочник нумерации (или без него, если набор
не российский: региональные признаки отключатся, остальное сработает). Детерминировано (часы движка идут
по времени вызовов из файла), результат воспроизводим.

## Запуск

```bash
cp .env.example .env        # заполнить POSTGRES_PASSWORD, пути справочника и модели
docker compose up -d --build
# с ML-сервисом:  COMPOSE_PROFILES=ml  (нужна обученная модель в каталоге моделей)
```

Справочник плана нумерации (реестр Россвязи: `ABC-3xx/4xx/8xx.csv`, `DEF-9xx.csv`) — данные вне git,
каталог задаётся `NUMPLAN_HOST_DIR`. Все переменные окружения описаны в `.env.example`.
Деплой на сервер — автоматически на каждый push в `main` (self-hosted runner, `docker compose up -d --build`).

## Обучение модели

```bash
go run ./cmd/export -numplan /path/to/numplan -out ./dataset       # признаки считает боевой движок
cd services/ml && pip install -r requirements-dev.txt
python -m training.train --data ../dataset --out models/current --report report.md
```

Подробности и результаты — `services/ml/README.md`. На синтетическом потоке (независимый набор): ROC-AUC 0,997;
review — полнота 97% при ложных срабатываниях 0,8%; ложных блокировок 1 из 177 тыс.; экстренных заблокировано 0.
Данные синтетические (`internal/synth`, с «трудными» легитимными абонентами: колл-центры, банки, курьеры, SIP-транки,
корпоративные мультисим), на реальных данных цифры будут другими. Честная проверка на независимом внешнем
датасете другой природы мошенничества (не просто другом наборе того же генератора) — и где система не
работает — [docs/external-validation.md](docs/external-validation.md).

## Известные ограничения

- Оператор по диапазону — это держатель диапазона; из-за переносимости номеров реальный оператор может отличаться (сигнал слабый и используется как признак, а не как вердикт).
- Регион — регион закрепления диапазона, а не местоположение абонента.
- Состояние окон хранится в памяти: после перезапуска окна прогреваются заново; масштабирование — маршрутизацией по хэшу номера.
- Корпоративные мультисим (много номеров одного абонента) дают повышенную долю `review`; в эксплуатации закрывается allowlist корпоративных номеров.
- Первый вызов подмены без истории модель оценивает неуверенно; для этого случая действует жёсткий пол `review`.
