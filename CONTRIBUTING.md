# Разработка

## Быстрый старт

```bash
make help            # все команды
make check           # lint + тесты (Go и Python) — гонять перед каждым коммитом
make demo URL=...    # сквозная проверка запущенного сервиса
```

Нужны: Go 1.25, Python 3.11+ (для `services/ml`), `staticcheck` (`go install honnef.co/go/tools/cmd/staticcheck@latest`), `ruff`.

## Структура

```
cmd/                 точки входа (decision-api, export, scorefile)
internal/
  api/               HTTP-слой
  decision/          решение: engine, decide, scoring, explain, mlclient
  detection/         признаки: enrich, window, graph, features, protect
  telecom/           предметная область: phone, numplan, callrec, ingest
  platform/          инфраструктура: store, journal
  lab/               синтетика и подготовка данных для обучения
services/ml/         ML-сервис (Python: CatBoost, scikit-learn, FastAPI)
scripts/             demo.py, retrain.sh
docs/                архитектура, безопасность, ML, эксплуатация, ADR
```

Правило зависимостей: слой может импортировать только нижележащие (`api → decision → detection → telecom`; `platform` и `lab` —
вспомогательные). Циклы и «обратные» импорты не допускаются.

## Порядок работы

1. **Ветка на задачу:** `feature/…`, `fix/…`, `refactor/…`. В `main` напрямую не пушим; слияние — после зелёного CI.
2. **Тесты обязательны** для нового поведения: не только «счастливый путь», но и ошибки, граничные значения, некорректный ввод, сбои
   зависимостей. Ошибка, найденная в эксплуатации, получает регрессионный тест.
3. **Инварианты безопасности** ([docs/safety.md](docs/safety.md)) нельзя ослаблять; изменения в `decide`/`protect` требуют тестов на инварианты.
4. **Существенное решение — новый ADR** в `docs/adr/` (что решили, почему, ограничения, последствия).
5. **Совместимость с Python-сервисом:** список и порядок признаков, биты сигналов и формат модели — контракты; их защищают тесты в обеих частях.

## Стиль

- Go: `gofmt`, `go vet`, `staticcheck` без замечаний; ошибки оборачиваем с контекстом; горячий путь без лишних аллокаций (проверяем `-benchmem`).
- Python: `ruff check` и `ruff format`; типы в сигнатурах публичных функций.
- Логи структурированные (ключ=значение), без персональных данных: номера — только маскированные.

## Коммиты

Сообщения на русском: краткий заголовок (что сделано) и развёрнутое описание (зачем, что изменилось, как проверено).
Секреты, ключи, реальные номера и содержимое `.env` в репозиторий не попадают.
