# ML-сервис (стадия 2 каскада)

Python-микросервис: CatBoost (монотонные ограничения) + калибровка Платта + точный TreeSHAP.
Go-ядро отправляет сюда только вызовы «серой зоны» (оценка линейной стадии не ниже ворот либо есть сильный сигнал),
остальной трафик решается в ядре за микросекунды. При недоступности сервиса ядро откатывается на линейную стадию.

## Обучение

```bash
# 1. выгрузить датасет признаков из Go (признаки считает боевой движок — рассинхрона нет)
go run ./cmd/export -numplan /path/to/numplan -out ./dataset
# 2. обучить, подобрать пороги и ворота, записать модель и отчёт
cd services/ml
pip install -r requirements-dev.txt
python -m training.train --data ../dataset --out models/current --report report.md
```

Что делает обучение: ранняя остановка по отложенной части, разбитой **по номерам** (без утечки);
вес легитимных ×3 (ложное срабатывание дороже пропуска); калибровка под ожидаемую долю мошенничества;
пороги review и block — по целевому FPR на отдельном наборе; ворота каскада — по полноте с пределом доли трафика в ML;
метрики — на третьем наборе, не участвовавшем в подборе.

## Запуск

```bash
MODEL_DIR=models/current uvicorn app.main:app_factory --factory --port 8100
```

| Метод | Путь | Назначение |
|---|---|---|
| GET | /health | статус и версия модели |
| GET | /v1/model | версия, признаки, пороги, метрики |
| POST | /v1/score | `{"features": {...}, "explain": true}` → score, вклады SHAP |
| POST | /v1/score/batch | до 500 векторов |
| POST | /v1/reload | перечитать модель (неудача не ломает текущую) |

Отсутствующий признак — ошибка 422, а не молчаливый ноль: так рассинхрон контракта с Go виден сразу.
Переменные: `MODEL_DIR`, `API_KEY` (если задан — заголовок `X-API-Key`).
